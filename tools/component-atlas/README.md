# 组件图册

一本能翻的册子：每页一个部件的一种设计做法，页面上直接是活的样子，旁边是它的代码。挂在工具箱侧栏「书籍」那一支下。

**这不是组件库**，是设计参考册 —— 翻它是为了回答「这个部件还能长什么样」。

完整的设计与取舍在主仓 `docs/组件图册形态设计-v1.md`。

## 目录

```text
tools/component-atlas/
├── tool.json          # 工具定义，唯一会被发布方读的文件
├── README.md          # 本文件。不发布
├── check.mjs          # 自查。不发布
└── site/              # 发布的就是这一个目录的内容
    ├── index.html     # 页面本体 + 分类树 TREE
    ├── data.js        # 全部内容
    └── img/           # 参考原图（可选）
```

发布之后 `site/` 整个拷到 `<装载基址>releases/tools_public/<版本>/tools/component-atlas/` 下，三个同级 —— 所以 `index.html` 里引 `data.js` 用相对路径就行。

## 树和条目是分开的

条目在 `data.js`，只有扁平的 `tags`；树是 `index.html` 顶部那份 `TREE`。两边互不认识，靠一条命中规则连起来（与工具箱壳 `catalog.ts` 里那条是同一条）：

```js
items.filter((item) => path.every((tag) => item.tags.includes(tag)))
```

所以 **想落在「部件 / 输入 / 会话输入框」下，就把这条链上的 id 一个个打上**：

```js
tags: ["部件", "输入", "会话输入框", "风格", "极简", "场景", "对话"]
```

- 打到你想要的那一层为止。只写 `["部件"]` 就只出现在「部件」下，不进任何子类。
- 两条链都打，就同时出现在两处 —— 跨类的做法不用选边。
- **链要连得上**：打了「会话输入框」却没打「部件」「输入」，这条在树上落不到任何位置，`check.mjs` 会拦。
- 树外的标签不拦，只提醒。与树一个都不重合的会掉进「未归档」。

要新分类：先往 `TREE` 里加节点，再给条目打上它的链。反过来不成立 —— 条目里凭空冒出来的标签在树上没有节点，落不进任何地方。

**树只放已经收到东西的路径，不预留空节点。** 这不是省事，是因为一屏 0 计数既占地方又误导：它看起来像「有 26 个部件」，其实一个都没收。真收了新部件再加一行，成本就是这一行。

## 加一条

只改 `data.js`，页面一行都不动：往 `CATALOG.items` 里加一个对象。

```js
{
  id: "input-underline",            // <部件>-<做法>
  name: "下划线输入框",              // 写法的名字，不是部件的名字
  tags: ["部件", "输入", "会话输入框", "风格", "极简", "场景", "对话"],
  summary: "一句话说清这个做法长什么样。",
  note: "一句话说清什么时候别这么长。",
  previewVw: 380, previewVh: 124,   // 组件的自身尺寸，两个都要给
  states: [
    { id: "default", label: "默认" },   // 第一条就是默认态
    { id: "focus",   label: "聚焦" }
  ],
  metrics: [
    { label: "高", value: "40px" }, { label: "底边", value: "1px / 聚焦 2px" }
  ],
  params: [
    { name: "h", label: "框高", min: 28, max: 56, step: 1, value: 40, unit: "px" }
  ],
  html: `<div class="field">…</div>`,
  css:  `.box{ height:var(--h); border-bottom:1px solid #d8d5cf }`
}
```

**完整的样子直接翻现在这一条**（`data.js` 里的 `composer-expand`）：两种形态靠纯 CSS 来回切、明暗两套、三根滑块接在 `--r / --pad / --btn` 上、图标全是内联 SVG 不挂外部文件。

### 五条容易踩的

1. **`params` 的名字必须与 `css` 里用到的 `var(--…)` 严格一一对应。** 多了漏了都不行 —— 滑块改不动预览，或预览里的值找不到滑块，这条就失真了。加完务必把每根滑块拉到两头，看预览会不会塌。
2. **状态要在 `css` 里接住。** 状态从外层写进预览 `<body>` 的 `data-state`，条目自己写 `body[data-state="focus"] …`。**第一条是默认态，它不用接**（页面打开就用它）；从第二条起必须接，不然切过去看不出变化。
3. **形态差异也靠状态切，别拆成两条。** 同一个部件「空着什么样、写起来什么样」是一个做法的一体两面，拆开就看不见它怎么生长了。高度、圆角、内部排布都能用 CSS 改，`composer-expand` 就是从 52px 的胶囊一路变到 197px 的卡片。
4. **要写两套色。** 明暗由工具页的开关带进来，同样是写进 `<body data-theme="dark">`。设计参考不写暗色等于只写了一半。
5. **不依赖任何外部资源。** 预览 iframe 不给脚本权限，也不该挂第三方图片与字体 —— 图标一律内联 SVG。组件自己那层底色（比如 App 的页面底）写在条目 css 的 `body{}` 上，不必迁就工具页那套暖色。

## 不收什么

| 不收 | 理由 |
| --- | --- |
| 需要 JS 才立得住的做法（下拉展开、轮播、动画开关） | 预览 iframe 不给脚本权限。要么用 CSS 把静态那几个状态画出来，要么不进这本 |
| 整屏结构 | 那是布局图册（`layout-atlas`）的地盘。判据：能不能从图上摘下来单独用 |
| 和已有某条几乎一样的 | 这本册子的价值在差异，两条长得一样等于稀释 |

## 加完要验什么

```text
node check.mjs                     # 数据自查，硬错误会拦下来
```

然后开页面走一遍：

- 在「部件」和「风格」两棵树下各点一遍，确认这条都出现在该出现的位置；
- 每个状态点一遍，看得出变化；
- 明暗各看一遍；
- 滑块拖到两头，预览不塌。
