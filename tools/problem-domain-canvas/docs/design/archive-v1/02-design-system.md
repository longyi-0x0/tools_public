## 1. 设计原则

5 条，每条给一条**可判定**的落实规则（判定动作写在「判定」列，实现者与评审者按同一句验收）。

| # | 原则 | 为什么是本工具 | 落实规则 | 判定（怎么算过） |
| --- | --- | --- | --- | --- |
| P1 | **深度就是背景色阶，不是投影** | 问题分解可以到 4–5 层，靠阴影堆层次会在深色里糊成一片 | 层级只能落在 `--pd-bg-app/surface/raised/overlay` 四层上；同一屏内嵌套不超过 3 层背景 | 取任意 3 处嵌套容器的 `background-color`，其值必须 ∈ {bg-app, bg-surface, bg-raised, bg-overlay}；且相邻层相对亮度差 ≥ 1.5 倍 |
| P2 | **语义靠形状 + 色带位置，不靠装饰** | 8 种节点 + 15 种关系，颜色不够用；色盲用户与灰度打印也要能读 | 8 种节点轮廓两两不同（含描边样式、色带位置）；关系线型（实/虚/点/双端帽）两两不同 | 截屏转灰度后，8 个节点剪影仍可两两区分；把色带全部置灰，节点类型判断正确率 ≥ 7/8 |
| P3 | **检查结果必须在视野内** | "缺什么"是这个工具的价值，藏在折叠面板里等于没做 | 任一 `阻断/警告` 检查项在右栏首屏或画布底部摘要条可见；点「定位」必须把锚点滚进可视区 | 1280×800 视口、未滚动状态下，画布底部摘要或右栏检查列表首屏至少出现 1 条检查；点定位后锚点矩形与视口相交面积 > 0 |
| P4 | **一个焦点，一个主轨** | 三种问题节点 + 六个领域元素同框，选中一多就不知道在改什么 | 同一时刻 `[data-selected="primary"]` 最多 1 个；选中领域元素时问题节点降为 1px 弱描边 | DOM 查询 `[data-selected="primary"]` 的 `length ≤ 1`；DOM 查询 `[data-selected="secondary"]` 允许 >1 |
| P5 | **没有无类型的像素** | 一旦允许自由文本块，它就退化成画板，问题结构失去可检查性 | 画布上不存在无类型节点、无条件边；新建必须先选类型 | 数据层每个 node 的 `type ∈` 8 枚举、每个 edge 的 `rel ∈` 15 枚举；UI 上没有"自由文本块"入口 |

## 2. 设计令牌

### 2.1 三层结构与命名

```text
原始层 raw       --pd-<家族>-<1..12>        只看色相与明度，不带用途
   ↓
语义层 semantic  --pd-bg-* / --pd-text-* / --pd-status-* / --pd-el-* / --pd-rel-* / --pd-sev-*
   ↓
组件层 component --pd-node-* / --pd-edge-* / --pd-tab-* …（只允许引用语义层与尺寸令牌）
```

规则：

1. 组件层令牌**禁止**直接引用原始色阶；只能引用语义层（换主题时组件无需改）。
2. 语义层**禁止**引用组件层；组件层**禁止**互相引用（`--pd-node-bg` 不得引用 `--pd-edge-bg`）。
3. 所有变量 `--pd-` 前缀，全部挂在 `.pd-app`（不是 `:root`），避免和宿主的壳程序变量打架。**Portal 例外**：模态/下拉/toast 挂到 `body` 末尾后拿不到 `.pd-app` 作用域，所以 Portal 容器必须同时带 `.pd-app` 类（`<div class="pd-app pd-portal">`），不允许退回 `:root` 兜底。
4. 深色是唯一实现的主题；浅色只留 `[data-theme="light"]` 的语义覆盖位（§8.4），本轮不写值。
5. 组件层可以有自己的组件令牌（`--pd-node-band`、`--pd-edge-w` 等，见 §8.6），但只能引用语义层与尺寸令牌；组件令牌不计入 §2.9 的 80 条核心令牌。

行高令牌：`--pd-lh-1: 16px`、`--pd-lh-2: 18px`、`--pd-lh-3: 20px`、`--pd-lh-4: 24px`、`--pd-lh-5: 28px`、`--pd-lh-6: 32px`。

字重：`--pd-fw-regular: 400`、`--pd-fw-medium: 500`、`--pd-fw-semibold: 600`。**不使用 700**：中文粗体在深色小字号下发糊。

字距（中文优先建议）：

| 令牌 | 值 | 用在哪 |
| --- | --- | --- |
| `--pd-ls-tight` | `-0.01em` | 只给 20/24px 的**西文与数字**标题；中文标题用 `0`，中文加负字距会挤掉字怀 |
| `--pd-ls-normal` | `0` | 12–16px 中文正文、导航、节点标签 |

### 2.7 间距 / 圆角 / 阴影 / z-index / 动效 / 线宽

**间距（4px 基模）**：`--pd-sp-1: 4`、`--pd-sp-2: 8`、`--pd-sp-3: 12`、`--pd-sp-4: 16`、`--pd-sp-5: 20`、`--pd-sp-6: 24`、`--pd-sp-8: 32`、`--pd-sp-10: 40`、`--pd-sp-12: 48`（单位 px）。不使用 4 的奇数倍（6/10/14），避免半像素。

| 令牌 | 值 | 用在哪 |
| --- | --- | --- |
| `--pd-r-1` | `4px` | 标签、边标签底、小按钮、count 徽标 |

| `--pd-r-3` | `999px` | 胶囊、状态点、参与者卡、缩放控件握把 |

| 令牌 | 值 | 用在哪 |
| --- | --- | --- |
| `--pd-shadow-1` | `0 1px 2px rgba(6,9,12,0.45)` | 节点默认、下拉、toast |
| `--pd-shadow-2` | `0 8px 24px rgba(6,9,12,0.55)` | 模态、抽屉、拖拽中的节点 |

| `--pd-z-toast` | `400` | toast（永远在最上层，且不参与点击拦截） |

动效（2 档时长 + 2 档 easing）：

| 令牌 | 值 | 用在哪 |
| --- | --- | --- |

| `#9BBDFF` focus ring | `#1A1F26` surface | **8.8:1** | 焦点环（非文本需 ≥3:1） | 通过 |

| `#464E5A` border-default | `#1A1F26` surface | **2.0:1** | 卡片边界 | **不达标** → 节点可点区域另靠 4px 色带 + 文字标识；需要"看得见的框"时用 `--pd-border-strong` |

结论（必须落到实现里）：

1. 正文永远不用 `--pd-text-4`；`n-6` 只出现在 ≥18px 或非文本场合。
2. 主按钮只能用 `--pd-accent-fill` 填充；azure-4 不做大面积填充。
3. 节点"边界"不是唯一信息载体：类型靠 4px 色带 + 图标 + 形状，所以默认边框 2:1 不构成无障碍缺陷；但**输入框、下拉、可键盘聚焦的容器**必须用 `--pd-border-strong`。

### 3.4 三处必须写死的细节

1. **右栏检查项的文案结构是固定三段**：`{严重度}· {缺什么}` / `{定位描述}` / `[定位]`。例如「警告· 缺反例」「P1.2 冲突检查 只有正例，没有反例」+ `定位`。不要写成"缺少反例，建议补充"这种没有锚点的句子。
2. **toast 只用于"刚刚发生的事"**：保存成功、迁移完成（沿用 `wireframe-lab` 的 `schemaVersion` 迁移链，迁移后提示一句"旧草稿已并入当前工程"）、检查项被忽略。检查结果本身不进 toast（进 summary 条与右栏）。
3. **空状态必须给出唯一主操作**：`问题总览` 空 → 「新建核心问题」；检查全过 → 不放按钮，只显示"当前未发现结构性缺口"（避免制造无意义动作）。

纵深上限：**建议 5 层**，超过 5 层时画布提示「分解过深，考虑把 P1.1.2.1 提升为独立问题」，并在节点上加 `depth-warning` 角标（不阻断）。

布局方向（与参考图一致，必须照做）：

- **纵向轴 = 抽象 → 具体，自下而上**：父节点在下、子节点在上。参考图里 P0 在下方、P1 在上方、中间一条竖线带「分解」标签，就是这个方向；实现时 `y(子) < y(父)`。
- 同一父节点下的子节点横向排列，父节点水平居中于子节点群的中心。
- 问题↔领域元素的连线为横向或对角，**不参与纵向层级轴**；领域元素固定吸附在问题节点的左右两侧（默认右侧，冲突时翻到左侧）。
- 视图内自动布局参数：横向兄弟间距 24；纵向层间距 96（含 20px 边标签空间）；层首节点 x 由内容包围盒居中。

### 5.3 缩放与滚动

| 项 | 规定 |
| --- | --- |
| 缩放范围 | 0.5 – 2.0；离散档 `[0.5, 0.75, 1, 1.25, 1.5, 2]`，`Ctrl/⌘ + 滚轮`连续缩放（每档 0.1，10ms 节流） |

### 5.4 栅格与对齐

- 画布采用 **8px 网格吸附**：节点 x/y 吸附到 8 的倍数；拖拽时显示 1px 虚线参考线（同轴其他节点中心/边缘）。
- 左栏与右栏采用**行高栅格 32px**（紧凑行）/ 36px（树形行）；分组标题高 24，与首行间距 8。
- 右栏属性行 `key` 占 40%（`min-width: 88px`），`value` 占剩余并右对齐；多选标签换行时左对齐。
- 所有文本容器禁止出现 `1px` 奇数内边距导致的半像素模糊：内边距只用 `--pd-sp-*`。

### 8.1 四个 CSS 文件的职责边界

| 源码文件 | 只负责 | 不负责 | 规模预期 |
| --- | --- | --- | --- |
| `src-web/styles/tokens.css` | `--pd-*` 全部变量；`@layer` 声明顺序；`[data-theme]` 覆盖入口；`prefers-reduced-motion` 的变量覆盖；`@media` 断点里对**布局变量**的改写（`--pd-nav-w` 等） | 任何选择器样式（除 `.pd-app` 与 `[data-theme]`） | 150–220 行 |
| `src-web/styles/base.css` | reset 最小集（`box-sizing`、`margin: 0`、`button/input` 继承字体）；`.pd-app` 布局骨架（三栏 grid）；滚动条；焦点环基线；文本工具类（`.pd-truncate`、`.pd-mono`、`.pd-sr-only`） | 组件外观；具体视图布局 | 120–180 行 |
| `src-web/styles/components.css` | §3 的 24 个组件（`.pd-topbar`、`.pd-tab`、`.pd-navitem`、`.pd-node-*`、`.pd-edge*`、`.pd-capsule`、`.pd-prop-row`、`.pd-check-item`、`.pd-empty`、`.pd-toast`、`.pd-modal`、`.pd-select`、`.pd-zoom`、`.pd-toolbtn` …）+ 状态修饰符（`[data-state]`、`:hover`、`:focus-visible`、`[aria-selected]`、`[aria-disabled]`） | 视图级排布（谁在左谁在右）；断点 | 500–700 行 |
| `src-web/styles/views.css` | 5 个视图的容器与排布：`[data-view="overview"]` / `detail` / `deps` / `elements` / `model`；画布视口与节点层；右栏分组；断点降级后的抽屉/底部面板定位 | 组件内部外观（改了就是越界） | 250–350 行 |

> 构建后：四个源码文件由 Vite 打包成 `site/assets/index-<hash>.css`（内容哈希命名），源码文件本身不进产物。

边界冲突的裁决规则：**外观在 components，位置在 views**。同一属性两边都想写时，components 用组件自身的间距（内边距），views 只用 `margin`/`grid` 做外部定位。

### 8.2 加载顺序与分层

源码侧入口 `index.html`（Vite 入口）按这个顺序引入，不合并、不打乱；构建后即使被 Vite 合并或改名，**层顺序仍以下面为准**（靠 `@layer` 声明兜底）：

```html
<link rel="stylesheet" href="./styles/tokens.css">
<link rel="stylesheet" href="./styles/base.css">
<link rel="stylesheet" href="./styles/components.css">
<link rel="stylesheet" href="./styles/views.css">
```

并在 `tokens.css` 顶部声明级联层（浏览器不支持 `@layer` 时自动退化为按加载顺序，两套结果一致）：

```css
@layer pd-tokens, pd-base, pd-components, pd-views;
```

四个文件内部各自 `@layer pd-tokens { … }` / `@layer pd-base { … }` 等。这样即便未来有人把 `components.css` 写在前面，层顺序也不会翻车。

禁止事项：不用 `@import`（多一次往返，且顺序不可控）；不用 CSS 预处理器；不引入 normalize.css 之类的第三方文件（base.css 自带 30 行以内的最小 reset）。

### 8.3 避免样式污染

| 措施 | 规定 |
| --- | --- |
| 变量作用域 | 所有 `--pd-*` 定义在 `.pd-app` 上，不写 `:root`；壳程序的变量不会被覆盖，反之亦然 |
| 选择器根 | 所有选择器以 `.pd-app` 开头（如 `.pd-app .pd-node-problem`），不允许裸标签选择器（`button {}` 这种一律禁止，除 base.css 里 `.pd-app button` 形式） |
| 类名前缀 | 统一 `pd-` 前缀；状态用属性（`[data-state="selected"]`、`[aria-selected="true"]`），状态类名（`.is-selected`）只在不便用属性时使用 |
| 全局副作用 | 不写 `html` / `body` 的全局样式（`height` 与 `overflow` 通过 `.pd-app` 自身撑满 `100dvh` 实现）；不改 `*` 选择器 |
| 重置范围 | base.css 的 reset 只在 `.pd-app` 内生效（`.pd-app *, .pd-app *::before, .pd-app *::after { box-sizing: border-box }`） |
| 命名冲突检查 | 实现完成后 `grep -o '\.pd-[a-z0-9-]*' src-web/styles/*.css | sort -u` 与 JS 里 `classList` 用到的名字对账，无孤类名（写了没用的类） |
| 第三方内联 SVG | 图标手写 16×16 path，`currentColor`，随主题变色；不引图标字体、不引 CDN 图标文件（§8.5） |
| React 边界 | 组件不接收任意 `className` 去覆盖令牌效果：`className` 只允许追加布局类（`margin`/`grid-area`），颜色与尺寸由变体决定 | 抽 3 个组件传入 `className="pd-x"`，视觉不变 |
| CSS Modules | 允许 `*.module.css`（Vite 原生支持），模块内仍只能 `var(--pd-*)`；不允许大段 `:global` 覆盖 | 抽查 module 文件，无颜色字面量 |
| Portal 作用域 | 挂到 `body` 的浮层容器必须带 `.pd-app` 类，统一由 `<Portal>` 组件注入，否则令牌作用域丢失 | 打开模态后 DevTools 看容器 class 含 `pd-app`，背景与文字色正确 |

### 8.4 主题切换（`[data-theme]` + 令牌覆盖）

深色为唯一实现主题；浅色只保留入口和覆盖位，**本轮不写浅色值**。

```css
/* tokens.css 里：语义层默认值（深色）写在 .pd-app 内 */
.pd-app[data-theme="light"] {
  /* 只覆盖语义层，原始色阶不动；浅色需要额外原始阶时按 2.3 的命名加 --pd-light-* 前缀 */
  /* --pd-bg-app: …; --pd-text-2: …; 本轮留空，等浅色设计定稿 */
}
```

规则：

1. 主题切换 = 在根容器上改 `data-theme` 属性：`<div class="pd-app" data-theme={theme}>`。只改属性，不重建组件树、不重载页面、不重新请求资源。
2. 只有语义层允许被主题覆盖；组件层不得出现任何颜色字面量（`#` 与 `rgb(` 只允许出现在 `tokens.css`）。
3. 主题选择持久化用独立 key（照 `persistence.js` 的"前缀 + schemaVersion"范式，`problem-domain-canvas:session:v1` 里存 `theme`），不塞进项目正文，避免迁移时连带影响文档数据。
4. 系统偏好只作为**初始值**（`prefers-color-scheme`），用户显式切换后以用户值为准；不监听系统变化改用户选择。
5. `data-theme` 切换时不触发重排（只改颜色），允许配 `--pd-dur-2` 的颜色过渡；`prefers-reduced-motion` 下取消过渡。

### 8.5 构建期资源约束

前提：Vite + React + TS，产物静态落到 `site/`，必须能在**离线**（`file://` 或内网静态服务器）打开。

| # | 约束 | 具体规定 | 验收 |
| --- | --- | --- | --- |
| EN1 | **字体只用系统字体栈** | 只允许 `--pd-font-sans` / `--pd-font-mono`（§2.6）。禁止 `@font-face`、禁止 Google Fonts / Typekit / 任何远程字体，禁止把 `woff`/`woff2`/`ttf` 提交进仓库或打进产物 | 产物内检索 `font-face`、`fonts.googleapis`、`.woff` 均为空；断网打开页面文字正常、无 FOUT、换机器不掉版 |
| EN2 | **图标要么内联 SVG，要么本地 sprite** | (a) 内联 SVG 组件（推荐，单图标 ≈200–400B，`currentColor`，随主题变色）；(b) 本地 `assets/sprite.svg` + `<use href="./assets/sprite.svg#icon-x">`，构建时作为同目录静态资源输出或用 `?raw` 内联。禁止 CDN 图标（Iconify API、unpkg）、禁止 icon font、禁止运行时 fetch 远端 SVG | `site/` 在断网下能渲染全部节点图标、3 档严重度图标与 24 个组件所需图标；产物里无远程图标地址 |

| EN4 | **无远程运行时依赖** | JS/CSS 全部由 Vite 打进产物；禁止 `<script src="https://…">`、禁止运行时 `import()` 远端 URL、禁止 CDN 样式表；`index.html` 除文档链接外无外链资源 | 产物 JS/CSS/HTML 里 `https?://` 只命中注释或白名单常量（外链文档、仓库地址） |
| EN5 | 体积预算 | 首屏 JS ≤ 180KB gzip（不含 React 运行时则整包 ≤ 320KB gzip）、CSS ≤ 40KB gzip、字体 0 字节 | `vite build` 报告 + gzip 实测；超预算先按 §8.7 裁库，不允许直接放宽 |
| EN6 | 零网络请求 | 运行期除本地静态资源外不发请求（持久化走 localStorage，无遥测、无 SW） | DevTools Network：交互 5 分钟后无第三方域名请求 |

### 8.6 令牌 → 组件映射约定

原则：**组件 props 只暴露语义对象，不暴露颜色与尺寸字面量。** `<NodeCard kind="concept" state="clarified" />` 合法；`<NodeCard color="#A78BFA" width={184} />` 一律不合法。

令牌三档权限：

| 权限 | 含义 | 谁可以用 | 举例 |
| --- | --- | --- | --- |
| 公开 | 页面/视图层可组合使用 | 视图容器、布局 | `--pd-bg-*`（经 `data-surface`）、`--pd-sp-*`、`--pd-r-*`、`--pd-fs-*` |
| 半公开 | 只能由对应组件映射成 `data-*` 属性，页面不得直接写样式 | 组件内部 | `--pd-status-*`、`--pd-el-*`、`--pd-rel-*`、`--pd-sev-*` |
| 内部 | 只在本组件/本文件出现，不对外 | base / components / views 各自 | `--pd-focus-*`、`--pd-z-*`、`--pd-node-band`、`--pd-edge-w` |

语义令牌 → props → DOM 属性（一一对应，不允许绕过）：

| 令牌组 | 组件 | props | 落到 DOM | 禁止 |
| --- | --- | --- | --- | --- |
| `--pd-bg-*` | `Surface` / 三栏容器 | `surface: "app"｜"surface"｜"raised"｜"overlay"` | `data-surface` | 用 className 改背景色 |
| `--pd-text-*` | `Text` | `tone: "1".."4"`、`size: 1..6` | `data-tone` `data-size` | 传 `color` / `fontSize` |
| `--pd-status-*` | `StatusDot`、`NavItem`、`NodeCard` | `state: "open"｜"analyzing"｜"clarified"｜"answered"｜"deferred"` | `data-state` | 传十六进制 |
| `--pd-el-*` | `DomainNode` | `kind: "actor"｜"scenario"｜"concept"｜"rule"｜"event"｜"example"` | `data-kind` | 用 kind 自行拼颜色 |
| `--pd-rel-*` | `Edge` | `rel: 15 个枚举之一` | `data-rel` + `data-group` | 传 `stroke` |
| `--pd-sev-*` | `CheckItem` | `severity: "blocker"｜"warning"｜"hint"` | `data-severity` | 传颜色或图标名 |
| `--pd-focus-*` | 全局 | 无 props | 只在 base.css 焦点基线出现 | 组件自定义 outline |
| `--pd-z-*` | `Modal`/`Drawer`/`Toast`/`Select` | 无 props | 四个浮层组件根 | 页面里随手 `z-index: 999` |
| `--pd-dur-*` / `--pd-ease-*` | 所有带过渡的组件 | 无 props | 组件内部 | 写 `transition: .3s ease` 字面量 |

组件层令牌（声明在 `components.css`，**不计入 §2.9 的 80 条核心令牌**，共 12 条）：

| 组件令牌 | 值 | 用在哪 |
| --- | --- | --- |
| `--pd-node-band` | 4px | 节点类型/状态色带厚度 |
| `--pd-node-rail` | 2px | 备注引线、规则双线的单线宽 |
| `--pd-edge-w` | 1.5px | 关系线线宽（选中 2.5px） |
| `--pd-edge-hit` | 12px | 关系线命中区宽度 |
| `--pd-port-size` | 12px | 端口命中区（视觉圆 6px） |
| `--pd-node-gap-x` | 24px | 兄弟节点水平间距 |
| `--pd-node-gap-y` | 96px | 纵向层间距（含边标签空间） |
| `--pd-grid-snap` | 8px | 画布吸附步长 |
| `--pd-nav-w` | 240px | 左栏当前宽度（断点改写） |
| `--pd-insp-w` | 320px | 右栏当前宽度（断点改写） |
| `--pd-topbar-h` | 64px | 顶栏高度（<1200 改 56px） |
| `--pd-edge-label-h` | 20px | 边标签高度（避让计算用） |

React 侧实现约定（与选哪个库无关）：

1. 样式写法优先级：CSS Modules + `var(--pd-*)` > 全局 `components.css` 的 `data-*` 选择器 > CSS-in-JS（不推荐：绕过令牌审计，且体积不可控）。
2. JSX 的 `style` 只承载**数据驱动几何**：`transform: translate(x, y)`、`width`、`height`、`left/top`；颜色、字号、圆角、阴影必须来自类名与令牌。
3. 视觉状态一律由 `data-*` 驱动（`data-state` / `data-selected` / `data-kind` / `data-severity`），不用 `.is-selected` 一类条件类名；这样能与 headless 库输出的 `aria-*` 自然对齐。
4. Portal 类组件（模态/下拉/toast）容器必须带 `.pd-app` 类（§2.1 规则 3），否则令牌作用域丢失。
5. 主题：根容器 `<div class="pd-app" data-theme={theme}>`，切换只改属性，不动组件树。

### 8.7 实现路径对比（A / B / C）

体积为 gzip 量级**估算**（含 React 18 运行时约 45KB），未经实测；选定后以 `vite build` 实测为准，并按 §8.5 EN5 卡预算。

| 维度 | A. 全自研 CSS + 极简交互 | B. headless（Radix primitives / Headless UI）+ 自研样式 | C. 完整 UI 框架（antd / shadcn/ui） |
| --- | --- | --- | --- |
| 对「语义化画布」的适配成本 | **低**：本设计系统就是自研，节点/边/胶囊零适配 | **低**：headless 不带视觉，令牌直接命中；只需按它的 Parts 结构对齐 DOM（Dialog/Select/Tabs 的解剖结构） | **高**：要把它自带的 token 体系（antd seed/alias token、shadcn 的 CSS 变量）映射到 `--pd-*`，双套维护；其默认密度/圆角/阴影会改掉三栏观感 |
| 额外自研工作量 | 高：焦点陷阱、listbox 键盘、tabs roving tabindex、树键盘、tooltip 定位、toast 队列 ≈ 800–1200 行 | 低：以上行为全部现成，只写样式与 `data-*` 映射 | 低，但要写大量覆盖样式；8 种节点与 15 种关系仍须自研，等于 C 的体积 + A 的工作量 |
| 产物体积量级 | 最小：≈ 60–90KB | 中：≈ 90–140KB（Radix 按需 15–40KB，或 Headless UI ≈20KB） | 大：≈ 350–500KB（antd 按需仍重；shadcn 体积小但等于把源码搬进仓库 + Radix 依赖） |
| 主题化难度 | **易**：只有 `--pd-*` 一层 | **易**：同样只有 `--pd-*`；需处理 Portal 的令牌作用域（§2.1 规则 3） | **中–难**：两套主题并存；12 个语义色（6 状态 + 6 类型）在框架 token 里没有对应槽位，只能逐组件覆盖 |
| 被框架带偏视觉语言的风险 | **无** | **低**：无默认外观；风险在 DOM 结构与 aria 约定，不在观感 | **高**：默认字体/圆角/阴影/密度会渗透，"看起来像 antd"会直接破坏语义化外观（尤其节点形状与关系线型） |
| 无障碍落地 | 自己保证（易漏细节，靠 §7 兜） | **强**：库已按 ARIA 实践；我们只需补视觉冗余（A3） | 强，但覆盖样式时容易连焦点环、禁用态一起覆盖掉 |
| 与 8 种节点 / 15 种关系的关系 | 完全受控 | 完全受控 | 无法借用其组件，只能自研 |

**推荐：B（headless）+ 画布自研。**分工：

| 层 | 方案 |
| --- | --- |
| 外壳交互（tabs、下拉选择、模态、toast、tooltip、开关） | Radix primitives（按需）或 Headless UI，**只引行为不引样式**；其 `className` 直接落到 `pd-*` 类名 |
| 画布（节点、连线、端口、缩放、平移、框选、拖拽） | **自研**：节点是绝对定位 DOM + CSS（文本换行与焦点好处理），连线是一层 SVG path（`vector-effect: non-scaling-stroke`），命中区用透明粗描边。**默认不引图库**（xyflow 之类）：它的节点/边抽象会反过来规定选中、拖拽与连线模型，而本工具的语义比它多 3 组关系与端口约束，覆盖成本高于自研（§8.8） |
| 图标 | 手写内联 SVG（§8.5 EN2/EN3） |

选 B 要接受的代价：tabs / tree / listbox 的键盘行为必须按库的 Parts 结构写 DOM，不能把 `role="tab"` 自己造一套再塞进库组件里；行为不符时先改自己的组合方式，不改库内部实现。

**无论选哪个，本文档的组件规格都按「行为 + 尺寸」写，不绑定具体库。**具体表现：

- §3.1 的"结构"只描述**可访问性角色与子元素顺序**，不规定标签层级（`div` / `span` 还是库的 Part）。
- §3.1 的"尺寸"是**视觉尺寸**（如 tab 高 32），不是任何库的 `size="sm"` 枚举。
- §3.2 的状态矩阵用 `data-*` 与 `aria-*` 表达；库若有自己的状态类名，必须映射到这套属性，而不是反过来。
- §3.3 的键盘表是**契约**：库不满足就换库或补实现，不允许出现"库不支持所以没有"。

### 8.8 若确实要引画布库（如 xyflow）：如何覆盖到本设计系统

只在 §8.5 EN5 预算允许、且自研工作量评估超出排期时才考虑；默认不引。允许引的前提是**外观 100% 由本设计系统决定**。

| 覆盖点 | 做法 |
| --- | --- |
| 样式来源 | **不引入库的默认样式表**（不 import `@xyflow/react/dist/style.css`）。所需基础样式写进 `components.css` 的 `/* pd-canvas-base */` 段，避免默认节点边框/阴影干扰 |
| 节点 | 自定义 `nodeTypes`，每个类型渲染 `pd-node-*` 组件；库外层 `.react-flow__node` 只留定位职责（`position` / `transform`），视觉一律由内层 `pd-node` 决定；`.react-flow__node-default` 等内置类不允许出现在 DOM |
| 端口 | 库的 `<Handle>` 覆盖为不可见（`opacity: 0; width/height: var(--pd-port-size)`），位置对齐 §4.1 的四向端口；可见圆点由自己的 `pd-port` 元素绘制 |
| 连线 | 自定义 `edgeTypes`，path 自己算（正交折线 / 三次贝塞尔按 §4.2 曲率系数）；`markerEnd` 换成自绘的 7 种端点（实心三角 / 开箭头 / 端帽 / 双端实心点 / 双向 / 圆点 / 无）；库的 `.animated` 一律不用 |
| 颜色变量 | 库暴露的 CSS 变量（`--xy-edge-stroke`、`--xy-background-color`、`--xy-node-border-radius` 等）全部映射到 `--pd-*`，让取色只有一条路径 |
| 优先级收敛 | 第三方覆盖统一放 `components.css` 末尾的 `/* pd-third-party */` 区块，用 `:where()` 降权；`!important` 只允许出现在该区块，且 ≤ 20 条、逐条注释原因 |
| 视觉验收 | §9 第 3、4 条按**灰度截图**验收：8 种节点形状、15 种关系线型必须与 §4.1 / §4.2 完全一致，与库的默认外观无关 |
| 红线 | 不允许因为库的默认值改本文档：节点尺寸、色带位置、线型、曲率、标签位置一律以 §4 为准；库做不到就换回自研，而不是改设计 |
