# lottery-new

池加抽奖两层结构。池是一类条目的集合，抽奖声明「从哪些池、按什么规则抽」，转盘、九宫格、老虎机只是浮在数据结构上的表演形式，换形式不改数据。

领域模型见 [`docs/wiki/抽奖领域模型.md`](../../../../../../docs/wiki/抽奖领域模型.md)。本实现按那份模型落地，术语与规则编号（R-01…R-20）都对齐。

## 模型

```text
Group   { id, name }                                     // 可选的去重范围

Pool    { id, name, entries: Entry[] }
Entry   { id, label, source, extKey,                    // id 由外部主键派生
          weight = 1, stock = 1, tags: [], meta: {} }

Draw    { id, name, groupId | null, slots: Slot[],
          form: { type, options }, mode }
Slot    { key, poolId, quota, scope,                    // 名额与作用域在这里
          count, replacement, weighted, hitRate, tags } // 抽取参数也在槽位上

Round   { id, drawId, groupId, seed, at, form, mode, win,
          slots,                                        // 开轮时的规则快照
          snapshot: { mode: 'full' | 'digest', boards },
          picks, sample, status }
```

池不分人员与奖品：人和奖是同一结构，差别只在新建池时模板给的默认值（人 `stock` 为 1，奖品可以多于 1）。引擎里没有按池类型分支的代码。

**槽位规则内联在槽位上**，不另开一张以 key 为索引的表。一一对应的东西分两处存，迟早有一处悬空。

## 四个领域概念

| 概念 | 含义 | 落在哪 |
| --- | --- | --- |
| **名额** `quota` | 一个槽位在整个抽奖里出几个奖，跨所有轮次累计，**不按轮重置** | 槽位；已出几个从账本算（`slotUsed`） |
| **库存** `stock` | 一个条目最多被抽中几次，跨池、跨抽奖共享 | 条目；剩余量从账本算 |
| **作用域** `scope` | 「中过就不能再中」管到哪一层：`draw` 本场 / `group` 同组 / `always` 全部 | 槽位；判据取轮次冻结的 groupId |
| **组** `Group` | 一层去重范围，不是文件夹。一个抽奖至多属一个组，可空 | 抽奖；删组不删抽奖，`group` 退化为 `draw` |

库存管「这个人还能中几次」，作用域管「在多大范围里数」，两者不是一回事：`stock = 1 + scope = group` 是「同组不重复中奖」；`stock = 1 + scope = draw` 是「本场不重复，换一场还能中」。

## 一次抽奖的六个环节

```text
装配候选 → 定结果 → 映射盘面 → 表演 → 入账 → （可选）复算
```

- **装配**读池成员、作用域内的用量、槽位剩余名额，算出此刻能抽谁（R-02 / R-03）。
- **定结果**按权重命中，结果在按下按钮的那一刻就定了（R-10）。
- **表演**拿只读快照，只负责把结果演出来，不写池、不写账本（R-12 / R-13）。
- **入账**写 picks，按 `round.id` 幂等（R-08）。
- **复算**用轮次自己的种子与候选快照重跑，逐项比对（R-07）。

## 不变量

1. 已中次数、剩余库存、槽位剩余名额，全部从账本派生，不另存计数（R-01）。
2. 只有 `settle` 写账，只在结算那一瞬间写一次；动画中断不产生账。
3. 撤销**不删记录**：占额作废、状态记 `undone`、命中原样留档（R-09）。
4. 撤销**只能撤最近一次结算**的那轮；想撤更早的，先把后面的按倒序撤掉（R-15）。
5. 撤销过的轮次不能再结算；`undone` 与 `discarded` 都是终态（R-19）。
6. 开轮那一刻把候选与规则冻进轮次快照，之后改池、改规则都不动这一轮（R-16 / R-17）。
7. 条目身份取外部主键 `(source, extKey)`：重复导入是更新，不是新建；缺主键的行拒绝导入（R-20）。
8. 同一轮里槽位按声明顺序（`a-then-b` / `b-then-a`）装配，前序命中对后序可见——次序是规格的一部分（R-18）。
9. 形式拿只读快照，输出只有「演完了」。

## 存取

存档只有一版在跑：`lottery-new:state.v2`。旧版 `v1` 第一次打开自动迁移——规则表并进槽位、`pickLimit` 搬成名额、组补空——原文另存 `lottery-new:state.v1.backup` 再删原键。

未结算的轮次可以丢弃（`discarded`），不产生占额。**不提供「作废」**：绕过账本排除某个条目会破坏「用量只从占额算」，要排除就改池或改作用域。

## 界面

两栏 + 两列：左边 240px 侧栏，底部 tabbar 在「抽奖」「池」之间切。「抽奖」是一棵树——组是父节点，抽奖缩进挂在组下，没进组的落在「未分组」；「池」是平铺的条目仓库。右边是详情页——标题、小节、行，分隔靠细线，不画卡片。

- **抽奖页**：名字、归属组、形式、抽取顺序、每个槽位的池 / 名额 / 作用域 / 抽取参数、开始、轮次台账。配置只在这一页改。
- **池页**：名字、条目（一行 `名字,权重,份数,工号`）、导入导出、已中次数（只读）。
- **组页**：点树上的组节点进来——组名、组里的抽奖（可直接点开）、在这个组里新建抽奖、删组（不删抽奖）。
- **轮次台账**：每轮的状态、时间、种子；`撤销` 只在栈顶可点，其余灰着并写清原因；`复算` 把结果贴在该轮下面。
- **开奖层**：盖住主页的全屏浮层，空格开始 / Esc 退出，演完自动入账。它只演结果，不抽奖也不写账本。

## 已知取舍

- **快照上限 2000 条**：一轮的候选超过这个数就只存摘要（`snapshot.mode = 'digest'`），复算会明说无法复算，而不是假装验过。这是本机存储的硬约束，不是能力缺失。
- **不做 xlsx 全量往返**：只读名单、导出记录与池。抽奖配置的整包导入导出不在这一版。
- **不做作废**：理由见「存取」。
- **老虎机的「未中奖」**按 `hitRate` 掷：候选不足两条时凑不出失败态，只能中。
