# lottery3

活动 → 环节两层。一场活动（2026 年会）下面按次序挂几个环节（三等奖、二等奖、一等奖），环节之间共享「中过还能不能再中」的范围，中过三等奖的人不会再中二等奖。

界面按两块屏、两种状态组织：**准备态**在笔记本上配好名单与奖项，**演出态**把控制台留给自己、把观众屏投给全场。

领域模型的前身见 [`docs/wiki/抽奖领域模型.md`](../../../../../../docs/wiki/抽奖领域模型.md)，v3 在这份模型上只做了加法（见「v3 改了什么」）。

## 谁在用

| 角色 | 什么时候 | 看哪块屏 | 要什么 |
| --- | --- | --- | --- |
| 策划者 | 活动前，独处，手上有 Excel | 笔记本 | 名单导得进、奖项设得对、能彩排 |
| 主持人 | 同一人，站上台那一刻 | 控制台 | 只有开始、下一轮、下一环节三个动作，零思考，不能手滑改配置；撤回上一轮只在待机时露面 |
| 观众 | 活动当场 | 投影大屏 | 名字够大、有悬念、看得出还剩几个 |

策划者与主持人是同一个人，所以没有第二套权限、第二套账号——只有**准备态 / 演出态**两个模式。

## 术语：界面说人话，模型照旧

领域词一个都不出现在界面上，全部经 `src/ui/labels.js` 这一处翻译：

| 模型里的词 | 界面上叫 |
| --- | --- |
| `Group` | 活动 |
| `Draw` | 环节 |
| `Pool` | 清单（人）/ 奖品清单（奖） |
| `Slot` | 出奖位，有名字（三等奖），不是「槽 1」 |
| `quota` | 共抽几个 |
| `count` | 一次抽几个 |
| `scope` | 中过还能不能再中 |
| `stock` | 能中几次 |
| `weight` | 中奖机会倍数 |
| `replacement` / `hitRate` | 收进「高级」，默认值不动就不必看 |

## 一次年会怎么走

**准备态**

1. 侧栏底部「＋」或空页上的「开始第一场活动」进向导，四步：这是什么活动 → 怎么抽 → 谁参与 / 抽什么 → 挑个外观。每步都有默认值，第三步可以直接粘一列名字或导入 xlsx，并在这一步定下**这个环节一共抽几个**、一次抽几个。
2. 导入先把这张表摊开：哪列是名字、哪列是工号、有没有份数与机会倍数，都由人在下拉里指。位置猜列猜错过一次，代价是某些人永远抽不中，所以这里不猜。
2. 活动页列出这场活动的环节卡片：名字、已抽 / 共抽、进度条、候选还剩几个。点「配这个环节」进环节页，点「上台开奖」直接进演出态。
3. 环节页是三段：开抽区（大按钮 + 本环节进度）、出奖位卡片（具名、内联选清单、高级默认折叠）、本环节记录（撤销只对最近一次结算可点）。
4. 清单页一行一项，行内即改；名字列按清单类型叫「名字」或「奖品」。

**演出态**

- 「开大屏」用 `window.open` 开观众屏，拖到投影上；没开成会明说「单屏模式」，不会假装在双屏。
- 空格开始，Esc 退出（演出中 Esc 无效，只在待机时可退）。
- 这次抽几个、从哪份名单抽、什么时候停——全在按下「开始」那一刻定完，动画只是演。演完自动入账，不给第二次点击的机会。
- 「彩排」走完整动画但不入账，用的是丢弃轮次的语义，不额外加字段。控制台整屏描边、观众屏挂横幅，台下也知道这是彩排。
- 待机时底栏有「撤回上一轮」：只撤栈顶那一轮，且彩排时不给。名字还亮在屏上时它不出现。
- 抽完一个环节，底栏出现「下一环节 →」，按 `Draw.order` 走。

## 两块屏怎么同步

控制台主窗口持状态、抽奖、写账本；观众屏是纯渲染端，不持状态、不写账本。

- 通道用 `window.opener.postMessage` 单向推，而不是 `BroadcastChannel`：`file://` 下后者的 origin 是 `null`，会失效。
- 指令四种：`ready`（摆好这一轮的盘）/ `spin`（转）/ `reveal`（亮名字）/ `rest`（收）。`ready` 带 `clear: false` 的那一次表示「刚抽完」，观众屏上的中奖名单要留着，不能抹掉。
- 待机时观众屏不是一块黑屏：控制台把这一轮的候选算成大屏盘面推过去，只画不转，第一下转动接着上一帧。
- 两边各跑各的动画，不做时钟同步——同步时钟只会让两边互相等。
- 观众屏不显示种子、不显示撤销、不显示「扇区等分」这类实现话术；清单名一律留空，台上不暴露「全员名单」这种内部叫法。

## 模型

```text
Group   { id, name, at }                                  // at：活动日期（v3 新增）
Pool    { id, name, kind, entries: Entry[] }              // kind：people | prize（v3 新增）
Entry   { id, label, source, extKey, weight = 1, stock = 1, tags: [], meta: {} }

Draw    { id, name, groupId | null, order, closed,       // order / closed（v3 新增）
          slots: Slot[], form: { type, options }, mode }
Slot    { key, poolId, quota, scope, label, manual,       // label / manual（v3 新增）
          count, replacement, weighted, hitRate, tags }

Round   { id, drawId, groupId, seed, at, form, mode, win, drawName,
          slots: [{ key, label, ... }],                    // 冻结的规则与名字（v3 不变量）
          snapshot: { mode: 'full' | 'digest', boards },
          picks, sample, status }
```

- **名额** `quota`：一个出奖位整场出几个，跨轮次累计，不按轮重置。
- **库存** `stock`：一个条目最多被抽中几次，跨池、跨环节共享。
- **范围** `scope`：`draw` 本环节 / `group` 同活动 / `always` 全部。新建默认 `group`——年会里「中过的不再中」才是常态。
- **`Slot.manual`**：这一位的人由主持人现场点选（先定奖项再抽人），引擎按它跳过抽取、只走进度与入账。
- **`Draw.order`**：同一活动内的次序，决定「下一环节」去哪。
- **`Draw.closed`**：这一环节封箱，不再出现在「下一环节」里。

## v3 改了什么

只做加法，`engine.resolve` / 账本 / 种子 / 快照结构 / 外部主键合并都没动：

| 编号 | 改动 | 为了 |
| --- | --- | --- |
| D1 | `Slot.label` | 出奖位有名字，不再显示「槽 1」 |
| D2 | `Slot.manual` | 「先定奖项再抽人」场景 |
| D3 | 轮次快照记 `slots[].label` 与 `drawName` | 改名不改史，复算页面看到的还是当时的名字 |
| D4 | `Draw.order` | 「下一环节」有确定去向 |
| D5 | `Draw.closed` | 封箱的环节不参与推进 |
| D6 | `Pool.kind` | 驱动界面叫「名字」还是「奖品」 |
| D7 | `Group.at` | 活动日期，活动页显示 |
| D8 | 默认 `scope` 由 `draw` 改 `group` | 年会默认跨环节去重 |
| D9 | 存档 `v3` + `v2`/`v1` 迁移 | 老存档能直接打开 |

存储层的两个魔法值（`quota = Infinity` 表示不限、`weight = 0` 表示不参与）**不动**：界面上换成独立开关，模型零改动。

## 3.0.0 改了什么（相对 2.0.0）

模型与引擎一行没动，改的全是「界面怎么把话说清楚、怎么不让人踩坑」：

| 编号 | 改动 | 为了 |
| --- | --- | --- |
| E1 | 活动页彩排走独立的 `onRehearse` 回调，不再靠给 `onStart` 多传一个参数 | 参数被中间层吞掉过一次，彩排按正式入了账，账本里分不出真假 |
| E2 | 演出层整屏描边 + 观众屏挂横幅标出彩排 | 台下会把彩排抽中的人当真 |
| E3 | 导入改成列映射对话框：四个下拉 + 预览 + 首行表头开关 | 按位置吞列把「部门」当成了机会倍数，归一成 0 就是永远抽不中，界面上什么都不显示 |
| E4 | 导出的四列（名字 / 能中几次 / 工号 / 权重）能原样导回 | 导出再导入不再错位，往返闭合 |
| E5 | 清单表格多一列「机会倍数」，倍数 0 的行标红 | 权重以前只存在于模型里，导入错了查不出来 |
| E6 | 向导第三步问「一共抽几个」「一次抽几个」，不限量做成显式开关 | 默认不限量等于把「什么时候算抽完」这个决定推给台上的主持人 |
| E7 | 演出层待机时给「撤回上一轮」 | 抽错人不必退出演出层、再倒着撤到那一轮 |
| E8 | 撤不掉的理由收进 `labels.js`，两处界面共用一份说法 | 说清楚是哪一条，而不是把按钮灰掉就算完 |

E3 的两条硬规矩：份数与倍数**读不出来就报错并拒绝导入**，不静默归一；倍数列没指定就一律 1，不许拿别的列顶上。

## 不变量

1. 已中次数、剩余库存、出奖位剩余名额，全部从账本派生，不另存计数（R-01）。
2. 只有 `settle` 写账，只在结算那一瞬间写一次；动画中断不产生账。
3. 撤销**不删记录**：占额作废、状态记 `undone`、命中原样留档（R-09）。
4. 撤销只能撤最近一次结算的那轮；更早的先按倒序撤（R-15）。
5. 演出层的撤回只在**待机时**可见，且彩排时不给：彩排没入账，那时露出来的「上一轮」是上一次正式抽的，一点就撤错了。
5. `undone` 与 `discarded` 都是终态，不能再结算（R-19）。
6. 开轮那一刻把候选与规则（含出奖位名字）冻进快照，之后改池、改规则、改名都不动这一轮（R-16 / R-17）。
7. 条目身份取外部主键 `(source, extKey)`：重复导入是更新不是新建；缺主键的行拒绝导入（R-20）。
8. 同一轮里出奖位按声明顺序装配，前序命中对后序可见（R-18）。
9. 形式拿只读快照，输出只有「演完了」。

## 存取

存档只有一版在跑：`lottery3:state.v3`。`v2` / `v1` 第一次打开自动迁移（补 `label` / `kind` / `order` / `at`，默认 `scope` 提到 `group`），原文另存 `.backup` 再删原键。

## 已知取舍

- **转盘自己画**：通用组件库把文字沿半径转，下半圈名字整个倒过来，投影上看不清。`forms/wheel.js` 改成自绘 canvas，名字一律水平直立，按扇区宽度自动缩字号、截断。九宫格与老虎机的文字本来就是正的，仍走组件库。
- **快照上限 2000 条**：超过就只存摘要（`digest`），复算会明说无法复算，而不是假装验过。
- **不做配置整包往返**：读名单、导出记录可用；抽奖配置的 xlsx 导入导出不在这一版。
- **导入不猜列**：列由人在对话框里指定。猜过一次，第二列「部门」被当成机会倍数、归一成 0，那些人永远抽不中且界面上看不出来。代价是多一步确认，不值得再省。
- **撤回不进揭晓态**：名字亮在屏上时不给撤，台下已经看见那个人了。要撤先收一下（下一轮自动收）。
- **彩排不隔离**：彩排不入账，但同一台机器上彩排与正式共用一份存档，靠不入账区分。换机器、清缓存照样什么都没了——存档导出不在这一版。
- **不做作废**：绕过账本排除某个条目会破坏「用量只从占额算」，要排除就改清单或改范围。

`rehearsal.mjs` 与 `import.mjs` 是 3.0.0 这两处修复的回归锁：前者守「彩排不写账本」，后者守「倍数读不出来不许导入」。

## 版本沿革

- **lottery**（第一版）：池 / 抽法 / 槽位 / 绑定的实现视角词汇，主页右栏五段配置，新建一步塞六个决策。
- **lottery-new**（第二版）：领域引擎重写——名额 / 库存 / 范围分清，一切计数从账本派生，实抽与复算同一段代码，撤销留痕，外部主键防重复。界面仍是模型的直接投影：参数表、`slot1`、组画成文件夹。
- **lottery3**（2.0.0）：引擎不动，界面全重做——活动 / 环节两层、术语词典、新建向导、准备态与演出态分离、观众屏单一适配。
- **3.0.0**（本版）：引擎还是不动。修了两条会毁掉现场的：彩排按正式入账、导入按位置猜列；补了三处组织者要的：向导问名额、倍数看得见、演出层待机能撤回上一轮。
